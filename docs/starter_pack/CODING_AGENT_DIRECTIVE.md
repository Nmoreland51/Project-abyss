# Project Abyss — Coding Agent Handoff

Read MASTER_AUDIT.md, SYSTEM_ARCHITECTURE.md, DEVELOPMENT_ROADMAP.md, TESTING_STRATEGY.md and REQUIREMENTS_TRACEABILITY.csv before editing. Treat them as the coordinated design baseline.

Your assignment is to implement an autonomous, evidence-driven research system that discovers overlooked useful tools and information ecosystems. Build open-world recognition as a scientific experimental module; use public research data and controlled authorized laboratory environments. No unauthorized access or interception. Clearly explain limitations and any proposed scope changes rather than silently redefining the objective.

## First execution
1. Inspect the current repository and environment, or initialize an empty repository if appropriate. Record baseline commit and test status.
2. Complete Phase 0 documentation with real sources, taxonomy, source registry, design choices, and benchmark definitions.
3. Produce a consolidated gap audit identifying what is implemented, missing, broken or not validated.
4. Implement the first approved phase as a coherent change set, including test and documentation changes.
5. Run real verification and full regression; report actual commands, results, artifacts, failures and limitations.
6. Update requirement traceability and propose the next phase based on evidence.

## Rules of evidence
Distinguish planned, implemented, simulated and independently verified. No fabricated research, fake live telemetry, invented sources or hidden changes to project goals. No final success claim without actual outputs. Use small local baselines before expensive infrastructure. Preserve user control over configuration and research objectives. Record scope, rationale, budgets and rollback decisions.

## Reporting format
Phase / baseline / audit findings / files changed / tests executed / measured results / unresolved issues / completion gate / next phase. Never report a test passed if it was skipped, mocked for a live requirement, or blocked.
