# Coding agent directive — RetroReddit V2
Read MASTER_AUDIT.md, SYSTEM_ARCHITECTURE.md, DEVELOPMENT_ROADMAP.md, DATA_AND_GOVERNANCE.md, TESTING_STRATEGY.md and REQUIREMENTS_TRACEABILITY.csv before editing. This supersedes V1's archive-browser architecture. If a repo exists, inspect current state, build/test baseline, list reusable modules and migration risks. Do not discard unrelated working code or alter production data without documented plan. If greenfield, initialize a reproducible repo.

Goal: real independent classic-style Reddit social app. Home is a normal feed; accounts, communities, posts, replies, votes, karma and search are live. Historical content is optional background seed, not the UI. Never depend on modern Reddit servers for core operation. Do not claim affiliation or transplant existing accounts. Build Phase 0 then Phase 1 vertical slice with real DB/API and Android client. Do not spend the first phase polishing an archive UI or building an overcomplicated microservice stack. Use modern supported dependency versions checked during implementation. Reuse historical code only with reviewed license compliance; distinct branding and assets.

At each phase: audit, implement related features together, run tests, record actual outputs, commit coherent changes, update traceability and status, and identify next blockers. Proceed through phases when gates pass; ask only for consequential owner decisions or credentials absent from context. Do not silently change objectives or governance. Explain proposed policy/technical restrictions and alternatives; applicable law, rights, privacy and authorization requirements still apply. Use synthetic/rights-cleared fixtures, never target removed violent content or bypass archive controls. No fake users, fake posts presented as real history, fake tests or simulated server success. Real device and independent backend verification required for release.

Deliverables: source, reproducible dev deployment, OpenAPI, migrations, tests, source permission manifest, sample fixture, operations manual, benchmark/security reports, signed APK and checksum at release. Keep public deployment separate from local pilot. At final audit demonstrate two real accounts posting/replying/voting on the same backend, app/server restarts, normal feed with approved imported material, search, offline recovery and archive outage independence. Optional Abyss integration only after core works. If a phase fails, record root causes and fix coordinated defects before claiming completion.
