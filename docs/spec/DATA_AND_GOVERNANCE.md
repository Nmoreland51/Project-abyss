# Data rights, historical provenance and platform governance
## Source inventory template
For each source record provider, URL, content types, access method, terms/license version/date, permission evidence, allowed use (reference/index/republication), rate limits, retention/removal contact, reviewer, decision and review date. Default unresolved reuse decision means no publication of that material; link/reference only where permissible. Availability of an API or code license does not establish a license to republish user posts. Check source terms at development and launch. Sources: archived Reddit code https://github.com/reddit-archive/reddit/blob/master/LICENSE ; Arctic Shift https://github.com/ArthurHeitmann/arctic_shift ; CDX https://github.com/internetarchive/wayback/tree/master/wayback-cdx-server . No live access tests performed for this audit.

## Identity and provenance
Imported author labels are historical attribution, never local accounts. Preserve original dates and source URLs where permitted. Local replies have local authors and timestamps. Archived scores separate from local vote/karma. Missing or inaccessible content remains missing; never generate replacement text. Track coverage by source, date, community, record count, rejected rows and reasons without claiming completeness.

## Import operations
Use rights-cleared sample dataset or synthetic fixtures first. Dry-run counts, malformed rows, duplicates, missing parents, rights decision and projected storage. Commit in bounded batches; maintain checkpoints and idempotency; reconcile parent relationships. Use normal source interfaces and rate limits; no circumvention. No targeting removed violent material or private information. Approved media may be attached only when reuse is authorized and source available. Removal requests propagate to visible records, search, caches, export feeds and objects; tombstones prevent reimport; backups expire per documented schedule. Do not preserve removed payload in logs.

## Policy decisions before public launch
Owner approves and documents community rules, moderation escalation, report response objectives, appeal route, privacy/retention, age-sensitive content presentation, distribution channel and user-facing terms. For lawful potentially disturbing content, document label and preview preferences explicitly; separate user preferences from required platform restrictions. Do not silently add or change policies. Legal and distribution compliance are not optional feature toggles. Review branding and hosting obligations with appropriate professional input for public launch. Private pilot is not exemption from applicable law. No unauthorized private content, exploitation material, or evasion of removals. Testing uses synthetic media.

## Operational model
Community moderators manage scoped communities; administrators handle platform-wide issues. Every moderation action records actor, target, reason, time, scope and appeal status. Access to audit logs is restricted. Report abuse and appeals have a defined review process. Users can block/mute, export/delete their local data and control notifications. No fabricated accounts, votes or activity. Publish changes to ranking and content policies; record explicit owner decision. Optional Abyss read-only API inherits visibility/removal state and never leaks private records.
